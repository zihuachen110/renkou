## 总结论

按路线图的 23 项站内 SEO 清单，当前 `ui-mockup/index.html` 达标约 **2/23**、部分达标约 **5/23**、未达标约 **14/23**。更关键的是：**产品定位与路线图的核心前提存在根本偏差**——前者直接决定后面所有细节值不值得投入。

## A. 战略层偏差（先决策）

路线图反复强调的硬前提，本项目目前均不满足：

| 路线图前提                | 原文依据                        | 本项目现状                          | 影响                                  |
| -------------------- | --------------------------- | ------------------------------ | ----------------------------------- |
| **必做英文/多语言站**        | Q6、阶段6：「海外 ECPM 是国内 5–30 倍」 | `lang="zh-CN"` 纯中文、中文内容        | 中文 ECPM 仅 0.2–0.5，英文 2–10；变现差 10 倍+ |
| **工具站优于内容站**         | 0.3、阶段1                     | 人口观是「数据探索/内容站」                 | 维护成本高、被动收入弱                         |
| **单域名单关键词，一个域名一个工具** | 0.3、避坑                      | 指标分散：总人口 + 老龄化 + 后续城镇化（PRD §1） | 权重分散，无法聚焦一个词打透                      |
| **域名与关键词相关**         | 1.3                         | `renkou` 拼音品牌名，非关键词域           | 品牌词难承接搜索词                           |

**性价比最高的一条杠杆**：给站加英文入口（`/en/`）吃 `China population` 这类高量词，用**子目录而非子域名**（路线图阶段6明确「重要：用子目录」）。收益远大于任何站内细节优化。

## C. 最致命的一条：渲染方式（路线图 2.3.5 / Q9）

路线图核心教训：「**爬虫看到的是 HTML 源码，前端渲染的内容爬虫看不到**」，动态页必须 SSR，否则所有页面 HTML 相同 → 判重复 → 不收录。

本项目当前恰好踩中：

* 所有人口数值、排名、表格均由 JS 在浏览器生成（`index.html#L695-L1059`）→ 爬虫拿到空壳。

* PRD 技术栈为 **Astro SSG**（`PRD.md#L186`），方向正确，但必须确保**每省数值/表格预渲染进 HTML**，不得沿用 mockup 的纯前端渲染。

**可顺手拿下的长尾红利**（路线图「详情页动态生成海量页面」打法，极适合数据站）：

> 给「省 × 年」生成独立预渲染页，URL 带 slug：`/province/guangdong-2020`、`/year/2020`。34 省 × N 年 = 数百个精准长尾页，每页 H1/title/description 随地区+年份变化。这是本项目唯一能对标路线图「海量长尾」的抓手。

## D. 页面类型与内链（路线图 2.1 / 2.3.6 / 2.3.7）

| 路线图页面类型     | 本项目对应               | 现状             |
| ----------- | ------------------- | -------------- |
| 首页（索引所有内页）  | `/`                 | 有，但内链全死链       |
| 工具/内页（一页一词） | 省份页、年份页             | ❌ 未规划独立 URL    |
| 详情页（动态长尾）   | 省×年页                | ❌ 未规划，且需 SSR   |
| 发现页（分页索引全部） | 「全部地区/全部年份」索引页      | ❌ 缺失           |
| 专题页         | 老龄化 `/topics/aging` | ⚠️ 仅锚点入口       |
| 关于 / 隐私     | `/about`、`/privacy` | ⚠️ PRD 有规划但未实现 |

缺「发现页 + 分页快进」= 爬虫无完整抓取入口，与路线图 2.3.6 / 2.3.7 直接冲突。

## E. 变现前提（路线图阶段5）

AdSense 审核硬门槛：**15+ 页面、privacy-policy、about、ads.txt、日 UV 50+**。

* PRD 目前 `ads.enabled=false`（`PRD.md#L165-L171`）且未规划上述合规页 → 上线时会被卡。

* 中文站 ECPM 低，**上英文版几乎是变现的必要条件**。

***

## F. 上线前最小动作清单（按性价比排序）

### P0（决定能否被收录 / 变现）

1. head 补齐：title / description / canonical / OG / Twitter / hreflang / JSON-LD（`Dataset` schema）——可直接改 `index.html` 做模板
2. 每页唯一 `<h1>` + 规范 H 层级
3. 改为 SSG 预渲染，杜绝数据纯 CSR
4. 真实静态路由 + `sitemap.xml` + `robots.txt`
5. 内链体系落地（替换所有 `href="#"`）

### P1（决定流量天花板）

1. 省×年长尾页矩阵 + 发现/分页页
2. 加 `/en/` 英文入口（子目录）+ hreflang
3. 隐私/关于页（AdSense 前置）
4. 自托管字体、压测 PSI

### P2

1. OG 分享图、结构化数据细化、外链/推广（路线图阶段3-4）
